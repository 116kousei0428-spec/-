# 野球ハンデ精算 PWA v7 Hardened

## v7で潰した構造上の問題
- 得点が入っただけでは精算しません。`status=FINAL` の確定結果だけを精算します。
- 中止 / 延期 / サスペンデッド / ノーゲームは受付・精算対象外です。
- ハンデを「試合」ではなく「各賭け登録」に保持します。同じ試合で別ハンデを安全に扱えます。
- 同一日・同一リーグ・同一カードの二重試合登録を防止します。将来自動取得を繋いだ場合は `externalGameId` を最優先で一意判定します。
- `startAt` が設定された試合は開始10分前で登録を締め切ります。
- 旧v6データは読み込み時に賭け側へハンデ情報を移して互換化します。
- 不正なハンデ / チーム / 金額を含む古い登録は誤精算せず「要確認」にします。
- PWAキャッシュをv7へ更新し、旧app.jsが残り続ける問題を避けます。

## 現在の操作
1. 「試合登録」でカードを登録（自動取得できない時の手動フォールバック）
2. 今日の試合から「＋ 賭け」
3. 名前 / 賭けるチーム / ハンデを出すチーム / ハンデ / 金額を登録
4. 結果はFINALとして確定した時だけ精算
5. 精算画面で日別合計を確認

## 自動試合・結果取得を接続する時の前提
試合データは、表示名ではなく外部の固定 `externalGameId` を保存してください。取得側から最低限次の形でアプリへ渡す設計です。

```json
{
  "externalGameId": "source-specific-id",
  "date": "2026-10-07",
  "league": "セ・リーグ",
  "teamA": "阪神タイガース",
  "teamB": "読売ジャイアンツ",
  "startAt": "2026-10-07T18:00:00+09:00",
  "status": "SCHEDULED|LIVE|FINAL|CANCELLED|POSTPONED|SUSPENDED",
  "scoreA": null,
  "scoreB": null
}
```

速報スコアが存在しても `FINAL` でなければ精算しないのが重要です。

## 配置
Cloudflare Pagesへ静的サイトとして配置できます。`index.html` がルートになるようにアップロードしてください。Firebase保存先は既存の `/blow2nd/baseball_handicap` を継続使用します。

## 注意
Yahoo!スポーツ等のHTMLをブラウザから直接解析する方式は、CORSやHTML変更で壊れやすいため、このZIPでは外部結果取得をまだ直結していません。自動取得はCloudflare Worker等のサーバー側アダプタ経由にするのが安全です。
